# 每日简报

在「面板设置 → 简报」选择时间、时区、包含的部分和是否让模型整理文字。自动发送默认关闭；启用前先配置「告警与通知」的通知出口。

简报可以包含总览中的警告、30 天内到期的资产和节点、过去 24 小时的警告与故障、在线节点数量、失败的后台任务。情报和日程模块通过只读的 `Brief` 接口补充内容，尚未安装或没有数据时略过。

程序先生成完整的数据版。启用模型整理且助理网关可用时，再调用不带工具的模型请求；20 秒内失败、空回答或返回工具调用时保留数据版，不执行任何模型动作。

## 调度与投递

- `brief.daily` 每小时检查一次，达到设置的本地时间后尝试发送；因此可能在设定时间后的一小时内投递。
- 使用 IANA 时区；编译时内置时区数据库，部署主机不必额外安装时区文件。
- 自动投递按本地日期持久化认领，重启、重复运行和夏令时重复时刻不会重复发送。
- 投递开始后若结果失败或未知，不自动重发，避免接收方收到重复内容。修复出口后可点「立即发送一份」手动重试；手动发送不替代当天的自动计划。
- 简报直接复用 Telegram、Webhook 或通知插件出口，不创建告警事件，也不经过告警节流与重试队列。
- 完整内容写入时间线；投递状态保存在 `brief_runs`，自动任务出错会显示在时间线页的定时任务状态中。Telegram 超长内容会截断，并提示到时间线查看全文。

## 接口与能力

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/admin/brief/settings` | 读取设置 |
| `PUT /api/v1/admin/brief/settings` | 保存 `enabled`、`time`、`timezone`、`sections`、`use_model` |
| `GET /api/v1/admin/brief/preview` | 预览已保存配置生成的简报 |
| `POST /api/v1/admin/brief/send` | 立即生成并发送 |

`sections` 可选 `overview`、`upcoming`、`events`、`nodes`、`jobs`、`intel`、`today`。

外部 agent 使用 `brief.preview`（Read）和 `brief.send_now`（Write），沿用访问密钥的模块和风险权限。

## 验证

`internal/brief/brief_test.go` 使用假时钟和假出口验证本地时间、跨日、重启去重、模型失败回退、失败不自动重放和手动重试。前端 ui-smoke 验证设置保存及预览。
