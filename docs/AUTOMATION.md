# 自动化规则（v3.8）

规则调用现有能力注册表：时间线新条目、五段 cron 或随机 Webhook 地址触发；条件支持 eq、ne、contains、gt、gte、lt、lte。新建页面默认停用。每条规则最小间隔 60 秒，最多 100 条规则、100 个待确认项。

时间线规则从创建时的三个来源游标开始，不补跑历史；自动化执行上下文产生的模块条目、告警、审计带 origin，全部排除。定时器只评估当前分钟，时区使用 IANA 名称，不补跑停机期间的时刻。Webhook 接受不超过 32 KB 的 JSON 对象，内容在模板的 `data` 中；公开响应只给 accepted，不返回私有能力结果。token 仅保存 SHA-256，新建或显式轮换时显示一次。

参数按 JSON 的值递归替换，例如 `{"body":{"title":"处理 {{title}}"}}`。整个值只有一个模板时保留数字、布尔值或对象类型；混合文本时按文本输出；找不到字段会失败。没有保险箱变量展开，不运行脚本。原参数不超过 32 KB，展开后不超过 64 KB。

创建和编辑同时要求目标能力权限；时间线规则还需 timeline 读取权限。创建者身份由服务端认证上下文保存。执行和确认前重新读取访问密钥，撤销、过期及范围调整立即影响后续执行。自动化不能调用自身的管理能力。能力调用继续经过统一的风险检查和原路由校验。

Read 和普通 Write 自动运行。Danger 以及标记 `Confirm` 的基础设施写操作（与助理同一名单，见 [ASSISTANT.md](ASSISTANT.md)）只保存冻结参数、发提醒并进入待确认队列；后台核对参数后确认或拒绝。确认者也需要目标能力权限。数据库条件更新先消费确认，再调用动作；失败和进程中断都不会重试同一次执行。启动时把不确定的 running 标记为 interrupted，需人工核实外部实际结果。

规则参数、冻结参数、执行结果通过保险箱加密；普通规则和执行记录不含这些内容。受保护详情为 Danger 能力，还检查目标能力权限。删除规则取消待确认项，保留执行记录；历史参数和结果仍是加密数据。数据库与 vault.key 必须一起保护，旧备份仍可能包含历史敏感信息。

每次尝试和结果进入时间线及审计，操作者为 `automation:<规则名>`。单动作最多 20 秒；超时不能证明外部副作用未发生，请核实后另行处理。此版本没有创建生产规则，也没有代用户生成外部服务配置。
