# 数字身份与安全（v3.9）

账户清单复用资产的 account 类型；密码和恢复码仍只保存在原保险箱，不复制到安全表。安全页记录两步验证（已开启 / 未开启 / 未确认）、恢复方式的存放位置和最后人工检查时间。「已人工复核」由服务端记当前时间，客户端不能伪造检查时间或检测结果。恢复位置只写描述，不填写恢复码。

## HIBP

全局开关和逐账户勾选都默认关闭。明确同意后，`security.passwords` 每天调度，成功检查过的同一个密码版本七天内不再查询；失败保留既有结果，隔日可重试。每次最多尝试 100 个账户。后台「检查已选密码」可人工重查，属于 Danger 能力，同时需要 assets 敏感字段权限；启用全局或逐账户检查也检查相应权限。

按 HIBP 官方 Range API，在本机计算 SHA-1，只把前五位发送到固定 HTTPS 地址 `https://api.pwnedpasswords.com/range/<prefix>`；设置 `Add-Padding: true`，在本地比对返回后缀，计数为零的填充项不会产生泄露告警。请求不带密码、完整哈希、邮箱、身份凭据或 Cookie，不使用环境代理，不跟随跳转；响应最多 1 MB，超时、异常响应与格式错误均为未知，不能变成「未命中」。对方仍能看到服务器的网络地址及查询时间。

实现依据为 HIBP API v3 的 Searching by hash range using k-anonymity 和 Introducing padding 两节：`https://haveibeenpwned.com/API/v3`。只验证前缀查询，不提供邮箱泄露查询。

数据库只保存计数、时间和错误状态，不保存完整密码哈希或查询前缀。结果绑定原保险箱密文的随机 nonce；密码重写后旧结果显示过期，不当成新密码的结果。查询期间密码改变时，旧请求结果也不会覆盖新版本。错误不会清除之前的命中记录。

首次发现命中或从命中恢复时写安全事件，通知沿用现有出口。未命中不能证明密码安全；密码出现在库中也不能证明这个账户被入侵。没有批量导入或设置生产密码。

## 域名、证书与登录

域名到期日来自资产登记；DNS 查询默认关闭，开启后每天用系统解析器检查域名是否有记录、是否解析到非公网地址。域名优先使用资产的「域名」字段，再尝试资产名称；无效名称保持未知。不请求解析地址的 HTTP 服务，不检查 DNSSEC、劫持或注册局到期日，解析失败与私网地址都需结合用途核实。证书风险读取现有证书状态、到期时间和错误标记，返回字段经过白名单筛选，不含私钥。

登录失败及缺少有效既有签名设备 Cookie 的成功登录进入安全提醒。有效设备凭据复用已有认证逻辑，改密码会使其失效；清理 Cookie、过期或换浏览器可能提醒。原始登录审计继续保留，新设备另写 login.new_device。每个记录来源的同类提醒五分钟内去重，状态跨重启保存；已识别设备的正常登录不额外提醒。来源链是记录值，不声明 IP 链可信。

访问密钥只授予 security 模块时，不会透出账户、域名或证书源数据；聚合接口分别检查 assets / certs 读取范围。普通读取不返回密码、恢复码和证书私钥。现有通知渠道没有配置时，事件会保留，遵循既有通知有效期与投递策略。
